# بيان | بیان — الإصدار الأولي 0.2.0

نسخة أولية قابلة للتطوير: واجهة تفاعلية ومشروع أندرويد وخادم إصدار رموز الاتصال. ليست نسخة منشورة أو ملف APK جاهزًا، ولم يُختبر محرك الصوت على جهاز أندرويد أو حساب Azure فعلي في هذه البيئة.

## ما الذي صُمّم ونُفّذ؟

- واجهة عربية/أردية من اليمين إلى اليسار؛ الترجمة هي مساحة القراءة الرئيسية.
- تكبير الخط من 26 إلى 60، مع تكبير إضافي في وضع المسجد. يحترم WebView إعداد تكبير النص على الجهاز.
- خط Noto Naskh Arabic مضمّن يدعم حروف الأردية دون تحميل خط من الإنترنت، مع إرفاق رخصته.
- حفظ حجم الخط والمظهر وعنوان الخادم واللغة محليًا؛ لا يُحفظ رمز الوصول.
- وضع داكن، ووضع مسجد يخفي التفاصيل الثانوية، وإبقاء شاشة الجهاز مضاءة أثناء الاستماع.
- جلسة خطبة الجمعة أو درس بعد الصلاة أو حديث ديني. هذه تسميات تنظيمية تستخدم المحرك نفسه؛ لا تفعّل نماذج متخصصة مختلفة.
- استقبال نتائج جزئية ثم مكتملة من Azure Speech Translation، من العربية إلى `ur`، بدون صوت ترجمة يزعج المصلين.
- إذن ميكروفون وقت الطلب، إيقاف الجلسة عند مغادرة التطبيق، ورسائل لفشل الشبكة أو المصادقة.
- تجديد رمز خدمة الكلام كل 8 دقائق للجلسات الطويلة.
- نص المقاطع المكتملة في ذاكرة الجلسة، بحد أقصى 500 مقطع. لا يُحفظ الصوت أو النص على قرص الجهاز بواسطة التطبيق.
- عرض توضيحي مستقل لا يستخدم الميكروفون ولا يحتاج خدمة؛ عباراته أمثلة تعليمية عامة غير منسوبة إلى آيات أو أحاديث.

## التجربة الآن

افتح `app/src/main/assets/index.html` في متصفح حديث، ثم اضغط «تجربة توضيحية بدون ميكروفون». تعمل أزرار الخط والوضع الداكن والمسجد ونص الجلسة. الاستماع الحقيقي يحتاج نسخة أندرويد وإعداد الخادم؛ المعاينة لا تتظاهر بترجمة صوت حقيقي.

## البنية

1. ميكروفون الهاتف → Azure Speech SDK داخل أندرويد → Azure Speech عبر اتصال الخدمة المشفّر.
2. تحويل الكلام العربي وترجمته إلى الأردية بواسطة الخدمة.
3. أحداث `recognizing` تحدّث المقطع الجاري، وأحداث `recognized` تثبّت المقطع المكتمل.
4. واجهة محلية داخل Android WebView تعرض النتائج. لا تُحمّل صفحات أو سكربتات خارجية.
5. خادم Node.js يحتفظ بمفتاح Azure ويصدر رموزًا قصيرة المدة للتطبيق. لا تمر بيانات الصوت بهذا الخادم.

هذه بنية Android هجينة: Java للتقاط الصوت ودورة حياة الخدمة، وHTML/CSS/JS للواجهة. ملف HTML هو الواجهة نفسها المضمّنة في التطبيق.

## بناء تطبيق أندرويد

المتطلبات المحددة لهذا المشروع: JDK 17، Android SDK Platform 35، Gradle 8.9، Android Gradle Plugin 8.7.3. الحد الأدنى للجهاز Android 8 / API 26. الاعتماد الصوتي المثبّت هو Microsoft Speech SDK 1.43.0؛ هذا تثبيت لإصدار معلوم وليس ادعاء أنه أحدث إصدار.

1. ثبّت Android Studio وSDK Platform 35 وGradle 8.9، ثم افتح مجلد `bayan` باعتباره المشروع.
2. يحتوي الأرشيف الآن على Gradle Wrapper الرسمي وملفات تشغيله والتحقق من بصمة التوزيعة؛ لا تحتاج إلى إنشاء Wrapper يدويًا.

3. اسمح بمزامنة واعتماد مكتبات Google وMaven Central. قد ينشئ Android Studio ملف `local.properties` لمسار SDK؛ لا ترفعه إلى مستودع عام.
4. على Linux/macOS:

```sh
./gradlew assembleDebug
```

على Windows:

```powershell
.\gradlew.bat assembleDebug
```

5. الناتج المتوقع بعد نجاح البناء: `app/build/outputs/apk/debug/app-debug.apk`. لم يتم إنشاء هذا الملف هنا.
6. ثبّت نسخة الاختبار على هاتف فعلي، وافتح «إعداد الاتصال» ثم أدخل رابط الخادم ورمز الوصول واختر لهجة الإدخال، ثم ابدأ الترجمة واسمح بالميكروفون.

## تشغيل خادم الاتصال

يتطلب حساب Azure ومورد Speech مناسبًا للمنطقة المختارة، وخادم Node.js 22 أو أحدث، ونطاق HTTPS بشهادة موثوقة. توجد تكلفة استخدام سحابية؛ لا توجد أسعار مفترضة أو اشتراك مفعّل في الملفات.

على خادمك أنشئ ملفًا خاصًا باسم `.env` داخل `server`، بدون رفعه إلى Git:

```dotenv
SPEECH_KEY=YOUR_AZURE_SPEECH_KEY
SPEECH_REGION=YOUR_AZURE_REGION
APP_ACCESS_TOKEN=YOUR_RANDOM_ACCESS_TOKEN_AT_LEAST_32_CHARACTERS
PORT=8080
```

استبدل القيم الرمزية بقيم حقيقية. ولّد رمز الوصول عشوائيًا؛ لا تستخدم المثال كما هو. شغّل من مجلد `server`:

```sh
node --env-file=.env server.mjs
```

الخادم يستمع على `127.0.0.1:8080` فقط. ضع reverse proxy يقدم HTTPS موثوقًا ويمرر `/token` إليه. التطبيق يرفض HTTP وإعادة توجيه رابط الرموز، ويطلب `POST /token` مع ترويسة Bearer. لا تضع مفتاح Azure في تطبيق الهاتف، ولا ترسله في المحادثة.

الرمز المشترك مناسب لتجربة محدودة يديرها مسؤول واحد. قبل خدمة مسجد كامل أو إطلاق عام، استبدله بمصادقة مستخدمين أو أجهزة ورموز قصيرة المدة قابلة للإلغاء، مع حصص استخدام لكل جهاز. الحد الحالي لطلبات الخادم مبني على عنوان الاتصال المباشر؛ خلف reverse proxy يكون حدًا مشتركًا، ويجب تصميم الحدود هناك للتوسع. لا تعتمد على حدود هذا الخادم وحدها لمنع إساءة استخدام رمز Azure بعد إصداره.

## جودة الترجمة الدينية

التطبيق يترجم الصوت؛ لا يسترجع تلقائيًا نص «رياض الصالحين»، ولا يتحقق من أرقام الأحاديث أو صحة نسبتها. لا توجد قاعدة قرآنية أو حديثية مدققة مدمجة. لا يعرض رقم آية أو حكم صحة حديث مستنتجًا من كلام غير واضح.

الترجمة الآلية قد تخطئ في الأسماء والمصطلحات والآيات والأحاديث. للاستخدام المنتظم، يلزم تقييم متخصص بالعربية والأردية على تسجيلات مأذون باستخدامها، ومراجعة حالات النفي والأوامر والأسماء. إن أُضيفت لاحقًا قاعدة ترجمات قرآنية وحديثية مراجعة، يجب التمييز بين نصها المرجعي والنص الآلي وعدم استبدال الكلام بمرجع غير متحقق منه.

الزمن الفعلي هنا يعني تحديثات متتابعة أثناء الكلام، وليس تأخيرًا صفريًا. التأخير يتأثر بالشبكة والمعالجة ووقفات المتحدث؛ قد تتغير الجملة الجزئية قبل تثبيتها. لا توجد أرقام تأخير مقاسة أو ضمان دقة في هذه النسخة.

## الصوت داخل المسجد

المسار المنفذ يستخدم ميكروفون الهاتف الافتراضي. اختبر قربه من صوت واضح؛ صدى مكبرات المسجد وكلام المصلين يضعفان النتائج. الربط المباشر بمخرج نظام صوت المسجد يحتاج واجهة صوت مناسبة واختبار توافق منفصل؛ ليس ضمن ما تم تنفيذه. لا يوجد بث مركزي لترجمة واحدة لجميع المصلين في هذه النسخة.

## الخصوصية والتشغيل

يُرسل الصوت إلى Azure أثناء الجلسة. عدم حفظ التطبيق للصوت محليًا لا يعني عدم معالجة مزود الخدمة له أو عدم وجود سياسات احتفاظ خاصة بالمورد. راجع إعدادات وسياسات المورد قبل الاستخدام الفعلي. رمز الوصول يُدخل في كل تشغيل ويبقى في الذاكرة؛ لا يستخدم التطبيق تخزينًا دائمًا له. إعدادات القراءة وعنوان الخادم واللغة فقط تُحفظ محليًا. يبقى نص الجلسة في الذاكرة فقط حتى بدء جلسة جديدة أو إغلاق التطبيق. الاستماع يتوقف عند الانتقال للخلفية؛ لا توجد خدمة استماع خلفية.

## التحقق وحالة التسليم

راجع `VALIDATION.md` لنتائج الاختبارات الفعلية. يلزم قبل النشر: نجاح بناء APK، اختبار إذن الميكروفون والخلفية وتدوير الشاشة، اختبار جلسة 45–60 دقيقة وتجديد الرمز، انقطاع الشبكة، أجهزة بمقاسات ونسخ Android مختلفة، قابلية قراءة الأردية، ومتطلبات توقيع وإصدار المتجر السارية. أضيف إعداد يسمح للواجهة بالاستجابة لتدوير الشاشة دون إعادة إنشاء Activity؛ يحتاج التحقق على جهاز فعلي. لا تحفظ النصوص تلقائيًا. لا توجد ادعاءات بأنها جاهزة للإنتاج.

## بناء APK باستخدام GitHub Actions

أُرفق ملف `.github/workflows/android-build.yml`. لم يُرفع المشروع إلى مستودع ولم يُشغّل هذا المسار على GitHub بعد.

1. أنشئ مستودعًا خاصًا باسم `Bayan` وامنح اتصال GitHub الوصول إليه.
2. ارفع **محتويات** مجلد `bayan` إلى جذر المستودع؛ يجب أن يكون `settings.gradle` و`.github` في الجذر، وليس داخل مجلد إضافي.
3. من **Actions → Build Bayan Android → Run workflow** شغّل البناء. ويعمل أيضًا عند الدفع إلى فرع `main`.
4. بعد نجاح المهمة نزّل **Bayan-Android-Debug** من **Artifacts** واستخرج `app-debug.apk`.
5. هذا APK للاختبار بتوقيع debug. لا يحتاج البناء إلى مفاتيح Azure؛ يمكن فتح العرض التوضيحي مباشرة بعد التثبيت. الترجمة الحية تحتاج إعداد خادمك داخل التطبيق.

الأرشيف يتضمن ملف العمل فقط؛ لا يوجد ادعاء بأن بناء GitHub نجح قبل تشغيله فعليًا.
